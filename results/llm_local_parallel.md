# Real-LLM ablation (small N), parallel tool calls

Generated by `python -m chaos.llm_ablation --provider ollama --model qwen2.5:3b --scenarios 50 --seed 0 --control --parallel` at commit `cd8367c`. Do not edit by hand.

50 scenarios x 3 configs completed.

Planner: `qwen2.5:3b` via Ollama tool calling, running locally on CPU (a reply without a tool call ends the run, as in a standard agent loop, so goal steps the model skips count as missing), at temperature 0.7, deciding from the goal and observed history only. The model may return several tool calls per reply, and is told it may when they don't depend on each other; the harness journals such a reply as one decision of several calls. Every scenario crashes once after a step between the first ad and the email (in-process crash injection), with 5% lost acks. LLM output is not reproducible run to run, and N is small: a check that the scripted-planner results carry over, not a benchmark.

A duplicate here can also be the model's own planning mistake (say, a fourth ad). `steps applied twice` tells the two apart: it counts effects from a step that had already taken effect, which only a re-send can cause. Any other duplicate is a new step the model decided. Without a journal to replay, `keys_only` numbers its steps from 0 again after a crash, so the column doesn't apply to it. The `harness, no faults or crashes` row measures the model's mistakes alone: same scenarios, same model, nothing to recover from.
